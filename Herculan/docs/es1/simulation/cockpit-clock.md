# DBSIM.EXE — the cockpit clock

**The cockpit's clock, a 24-hour display in its panel, opens the HERC's [animation script](cockpit-ttm-scripts.md) when it is made.** `es2_xref.py` finds one call of `Ttm_Open`, from `CockpitClock_Ctor` (`ES1DBSIM 000433cc`), which `CockpitClock_Create` (`ES1DBSIM 0002ce98`) calls with the panel and its description's `+0x644`, adding the clock to the panel's list at `+8` (the count at `+0x6c`). The clock is a `0x8a`-byte object, built on `00031318`, whose vtable `00094b5a` is held at `+0x76`. Addresses are `ES1DBSIM` image addresses.

`CockpitClock_Ctor` opens `ttm\` and eight characters `.ttm` (`Path_WithExtension`) with *a* and *b* 0, playing once without looping: the eight characters at `000925f8` when that is set, and otherwise the chassis name, file offset 86 of the [chassis file](../formats/chassis-dat.md), at `+0x58` of the type record `+0x188` of `CockpitViewInstance`'s (`00092d1c`) `+0x1ff`. It stores `CockpitViewInstance`'s `+4` at the script's `+0x1bd`, so the script draws through that render context, and keeps no handle. It takes the handle as a signed byte: when the open fails, the `0xff` reads the dword before the handle table as the script, and stores `+0x1bd` through it when it is not 0. The chassis without a script are types 8 to 15, which the player never pilots, so a retail cockpit's open finds its script. It then copies `cpwincrk` into its name buffer, which it does not read again, sets the strings `00`, `00` and `:` at `000bd504`, `000bd508` and `000bd50c`, makes three labels with `Label_Ctor` on the first of `ColorSchemePanels`' (`00092d40`) ten fonts, `cpblue`, at `+0x7a`, `+0x7e` and `+0x82`, and sets `+0x86` to the count `000981c4` + 30.

**The clock's three labels share one rect, so the hours' fill wipes the colon, which makes it blink.** The clock's rect, passed to `PanelGauge_Ctor`, is the description's `+0x654`, the `.GAU` file's offset 1620, 16 bytes into the clock's block at 1604 ([the layout](../formats/gau-cockpit-layout.md#differences-from-es2)). Each label gets that rect from `Label_SetRect` ([labels](cockpit-widgets.md#labels)): the hours with flags 1, left-aligned, and the margin (1, 0); the minutes with flags 4, right-aligned, and (1, 0); the colon with flags 2, centered, and (0, 0). Their fill colours `+0x1c` are `0x3f`, 0 and 0, so `Label_SetText` fills the rect with colour `0x3f` before it draws the hours and draws the minutes and the colon over what is there. `CockpitClock_Advance` sets the hours, then the minutes, and the colon only on every second call, so the colon shows for half a second and is wiped for the next half.

`CockpitClock_Tick` (`ES1DBSIM 000435c0`, the vtable's `+0xc`) sets the mark `+0x75` to 2 while the view manager's `+0x18` is set, a view change staged; while the mark is not 0 it copies the rect from the hour label's first corner to the minute label's second with `Widget_DrawToCockpit`(0, rect, 0), which copies from the display's page `+0x88` to `+0x8c` without the test of `000b5bca` its copy the other way makes and returns without copying while the view manager's `+0x18` is set ([drawing it](cockpit-panel.md#drawing-it)), and clears the mark. When `000981c4` is above `+0x86`, compared unsigned, it calls `CockpitClock_Advance` (`ES1DBSIM 00043658`), sets `+0x86` to the count as it read it before the call plus 30, half a second of the clock's 60 counts a second ([the tick length](fixed-point-math.md#the-tick-length--time_beginsimtick-00063f40)), and sets the mark to 1. `CockpitClock_Advance` toggles the byte `00094b56`, and on every second call adds a minute: the minutes run from 00 to 59 and the hours from 00 to 24, the hour after 24:59 being 00:00. When `CockpitView_RectCornerVisible`(the hour label's rect) is not 0 it sets the hour and minute labels' text with `Label_SetText`, and the colon's while `00094b56` is 1, between `Cockpit_PushCanvasContext` and `Cockpit_PopRenderContext`. `CockpitClock_Update` (`000435b0`, the `+8` slot) calls `CockpitClock_Advance`; the `+4` slot (`000435a1`) returns and the `+0x10` (`000435a7`) returns 0. None of the four touches the script.

The name at `000925f8` comes from the command line: the option `-C` passes the text after it to `CockpitChassis_SelectByName` (`ES1DBSIM 00024394`), which compares it, ignoring case, with the eight names `ROADRUNNER`, `GUNSLINGER`, `RAPTOR`, `TOMAHAWK`, `PATRIOT`, `PANTHER`, `HERCULES` and `COLOSSUS` at `00092644`, and for the first that matches stores its place at the word `CockpitOverride_Index` (`000925f4`) and the text's address at `CockpitOverride_Name` (`000925f8`). `CockpitViewManager_Ctor` (`ES1DBSIM 00021dd4`) takes the same pair in place of the HERC's chassis ([the view manager](cockpit-views.md#the-view-manager)). Eight characters of the eight names are the names of `ROADRUNN.TTM` to `COLOSSUS.TTM`, chassis types 0 to 7 ([the chassis files](../formats/chassis-dat.md)).
